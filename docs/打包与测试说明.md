# 打包与测试说明

## 一、Maven 打包时为什么会跑测试？

Maven 的**生命周期**里，`package` 阶段依赖前面的阶段，顺序是：

```
validate → compile → test → package → verify → install → deploy
```

也就是说：执行 `mvn package` 或 `mvn clean install` 时，会先执行到 **test** 阶段，**所有符合命名约定的测试类都会被执行**（例如 `*Test.java`、`*Tests.java`、`*TestCase.java`）。  
只有 **test 阶段全部通过**，才会继续执行 package，生成 JAR。**只要有任意一个测试失败（Failure/Error），构建就会失败，不会生成可用的 JAR。**

所以：**不是“打包顺带跑测试”，而是“先跑测试，通过了才打包”。**

## 二、你遇到的两个错误原因

| 错误 | 原因 |
|------|------|
| `TravelMasterTest.doChatWithRag` | 该用例会调用 `TravelMaster.doChatWithRag()`，内部使用 **PgVectorStore** 连接 PostgreSQL。若配置的 `jdbcUrl` 不可用（例如缺少数据库名、网络不通、或 HikariCP 与 URL 不兼容），就会报错。 |
| `OllamaTest.testOllama` | 该用例会连接本机 **Ollama** 服务（默认 `http://localhost:11434`）。若本机未启动 Ollama，请求会失败。 |

这两个测试都**依赖外部环境**（数据库、Ollama），在无环境或配置不对时会导致打包失败。

## 三、如何“取消测试”确保打包成功

### 方式 1：命令行跳过测试（推荐，最直接）

```bash
mvn clean package -DskipTests
```

- **效果**：不执行任何测试，直接打包。测试代码仍会编译。
- **适用**：本地/CI 只想产出 JAR、不跑测试时使用。

### 方式 2：使用 profile 跳过全部测试

```bash
mvn clean package -P skip-all-tests
```

- **效果**：与上面类似，通过 Maven profile 将 `skipTests` 设为 true。
- **适用**：不想记 `-DskipTests` 时，可用该 profile。

### 方式 3：不编译也不执行测试

```bash
mvn clean package -Dmaven.test.skip=true
```

- **效果**：测试代码不编译、也不执行，打包更快。
- **适用**：确定不需要测试时使用。

## 四、项目里已做的修改（在“跑测试”的前提下保证通过）

1. **OllamaTest**  
   - 在 `pom.xml` 的 **maven-surefire-plugin** 里已**排除**该类，打包时不会执行。

2. **TravelMasterTest.doChatWithRag**  
   - 已在该方法上增加 **@Disabled("Requires PostgreSQL and PgVector; ...")**，默认不执行；有可用 PostgreSQL + PgVector 时再去掉 @Disabled 即可运行。

这样在**不**使用 `-DskipTests` 时，只要本机有 DashScope 等配置、且不依赖 Ollama/PostgreSQL，其余测试可以照常跑，打包也能通过（注意：部分用例会调真实 API，耗时较长）。

---

## 五、日常建议

- **只想快速打出 JAR**：使用  
  `mvn clean package -DskipTests`
- **要跑测试再打包**：直接  
  `mvn package`  
  并保证不依赖不可用的 Ollama/PostgreSQL（或已排除/禁用相关用例）。
- **产出路径**：打包成功后，可执行 JAR 位于  
  `target/sy-ai-agent-0.0.1-SNAPSHOT.jar`  
  运行示例：  
  `java -jar target/sy-ai-agent-0.0.1-SNAPSHOT.jar`
