# 打包与测试说明

## 一、Maven 打包时为什么会跑测试？

Maven 的生命周期里，`package` 阶段依赖前面的阶段，顺序是：

```text
validate -> compile -> test -> package -> verify -> install -> deploy
```

也就是说：执行 `mvn package` 或 `mvn clean install` 时，会先执行到 `test` 阶段。只有测试阶段通过，才会继续生成 JAR。

---

## 二、测试分层

项目目前把测试分为两类：

| 类型 | 说明 | 默认执行 |
|------|------|----------|
| 默认测试 | 快速、稳定、不访问外部服务的测试，例如 Spring 上下文启动基线 | 是 |
| 集成测试 | 真实模型 API、SyManus 多工具链、搜索、网页抓取、下载、PDF、终端、文件写入、数据库/RAG 等 | 否 |

集成测试统一使用 `@Tag("integration")` 标记，并由 Surefire 默认排除。

---

## 三、常用命令

### 1. 运行默认快速测试

```bash
mvn test
```

只执行快速测试，适合日常重构后的反馈。

### 2. 运行包含集成测试的完整测试

```bash
mvn test -P with-integration-tests
```

需要可用的 DeepSeek Key、搜索 API、数据库、网络连接等外部环境。

### 3. 打包但跳过测试执行

```bash
mvn clean package -DskipTests
```

测试代码仍会编译，但不会执行。

### 4. 打包且跳过测试编译与执行

```bash
mvn clean package -Dmaven.test.skip=true
```

速度最快，但不会验证测试代码是否还能编译。

### 5. 使用项目 profile 跳过全部测试

```bash
mvn clean package -P skip-all-tests
```

等价于在项目 profile 中启用 `skipTests`。

## 四、常见失败原因

| 用例 | 原因 |
|------|------|
| `TravelMasterTest` / `AiChatTest` / `SyManusTest` | 会调用真实 DeepSeek API，Key、额度或网络不可用时会失败 |
| `TravelMasterTest.doChatWithRag` | 依赖 PostgreSQL + PgVector，默认仍用 `@Disabled` 禁用 |
| `WebSearchToolTest` / `WebScrapingToolTest` / `ResourceDownloadToolTest` | 依赖外部网络或第三方搜索服务 |
| `PDFGenerationToolTest` / `FileOperationToolTest` / `TerminalOperationToolTest` | 会产生文件或执行本机命令，默认作为集成测试隔离 |

---

## 五、日常建议

- 日常改代码：`mvn test`
- 打包产物：`mvn clean package -DskipTests`
- 发版前或演示前：准备好外部环境后运行 `mvn test -P with-integration-tests`

打包成功后，可执行 JAR 位于：

```text
target/sy-ai-agent-0.0.1-SNAPSHOT.jar
```
